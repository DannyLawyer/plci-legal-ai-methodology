# PLCI：法律 AI 实践方法论

> 面向法律工作的可追溯知识流程：让 AI 负责协助整理与起草，让来源、状态、权限和最终判断保持可见。

[English overview](README.en.md) · [许可协议](LICENSE)

## 这是什么

PLCI 是一套文档优先（documentation-first）的法律 AI 实践方法论。它关注的不是把法律工作包装成“自动得出答案”的产品，而是把资料、知识表达、合同起草素材和人工决定放进一个可区分、可追溯、可复核的流程。

这一方法特别适合需要同时管理法规、案例、解读、合同文本及内部工作判断的场景。AI 可以加快资料整理、候选提取和结构化表达；但来源可靠性、法律适用、条款复用和最终结论始终需要人工判断。

## 它解决什么问题

法律 AI 工作流的常见风险不是“模型没有写出内容”，而是内容在流转中失去边界：

- 摘要被误读为原文，或结论无法回到具体依据；
- 来源转录是否正确、引用是否完整、法律观点是否经审查被混为一件事；
- 合同条款的文字出处被误当成法律依据，或候选文本被误当成可直接使用的模板；
- 自动化修改缺少权限、版本和恢复边界。

PLCI 以“分层保存、精确定位、状态分离、人工把关”为核心，降低这些风险。

## 核心原则

| 原则 | 含义 |
| --- | --- |
| 来源优先 | 先保存并定位原始材料，再生成知识表达或起草候选。 |
| 可追溯 | 关键陈述应能回溯到其覆盖范围明确的来源片段。 |
| 状态分离 | 转录核对、引用完整性、内容审核、复用许可和最终批准分别记录。 |
| 人工最终决定 | AI 生成的是草稿、候选或待核实线索，不自行完成法律判断或授权升级。 |
| 最小权限 | 自动化只做被授权的动作；不确定时停止、说明原因并交由人工处理。 |
| 可恢复变更 | 对身份、路径、状态或审核记录的改动保留可审阅的变更与恢复依据。 |

## 这份仓库展示的能力

- 将法律 AI 流程拆分为原始资料、知识表达、起草资产、治理记录四类对象；
- 用精确定位、稳定身份与版本意识维持证据链；
- 设计 human-in-the-loop 审核门槛，而不是用模型输出替代专业判断；
- 为合同条款设置出处、法律依据、复用许可和适用条件的独立边界；
- 把数据最小化、可恢复修改和公开化审查作为系统设计的一部分。

## 公开范围与非主张

本仓库只公开方法论说明，所有文本均为重新撰写的概念性材料。它不包含代码、真实来源、合同或条款正文、案例材料、个人笔记、审核记录、运行数据或内部项目文件。

本仓库：

- **不提供法律意见**，也不替代律师、法务或其他合格专业人士对具体事实的分析；
- **不构成可直接部署的软件产品**，不承诺特定技术实现、性能或结果；
- **不替代对具体来源、许可或法律适用性的审查**，公开描述不能作为任何交易或合规决策的唯一依据。
